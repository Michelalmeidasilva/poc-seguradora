# Local Deploy Simplification Implementation Plan (Plan 8)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the GitHub-Actions deploy (Plan 7) by a local, script-driven deploy run from the operator's laptop: one script `infra/deploy.sh` with subcommands (`bootstrap`, `build`, `deploy`, `rollback`, `smoke`, `status`, `destroy`), using the operator's own `gcloud` login. Remove everything that existed only to support the CI deploy: the deploy workflow, Workload Identity Federation, the `deployer` service account and its roles, the GitHub environment/variables/tag-ruleset setup and the `github_*` Terraform variables. CI (`ci.yml`) keeps `verify` and the image-build job.

**Architecture:** `infra/deploy.sh` (bash 3.2 compatible) reads non-secret configuration from a git-ignored `infra/deploy.env` (example committed), checks prerequisites, and orchestrates `gcloud` / `docker buildx` / `terraform` / `node infra/smoke.mjs`. Terraform no longer creates any identity for automation: it is applied by the operator (their `gcloud auth application-default login`). The script is testable offline through fake `gcloud`/`terraform`/`docker` binaries placed first on `PATH` that record their invocations.

**Tech Stack:** bash 3.2, gcloud, docker buildx, Terraform ≥ 1.10, Node 22 (smoke). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-10-whatsapp-chatbot-poc-design.md` section 12 (Deploy); supersedes the GitHub-Actions part of `docs/superpowers/plans/2026-10-11-deploy-ready.md` (Plan 7). Everything else from Plan 7 (Dockerfiles, compose, smoke, nginx, Terraform services/network/secrets/budget, fake-services) stays.

## Global Constraints

- **Nothing in this plan calls GCP.** No real `gcloud`, `terraform plan/apply`, docker push or workflow run. The script is exercised only against fake binaries; Terraform is verified with `fmt`, `init -backend=false`, `validate`.
- **Safety defaults of `deploy.sh`:** every command that changes cloud state prints what it will do and asks for a typed confirmation unless `--yes` is given; `destroy` always requires typing the project id (even with `--yes`, it requires `--confirm-project <id>`); `deploy`/`build` refuse a dirty git tree unless `--allow-dirty`; `build` refuses to overwrite a tag that already exists in the registry; `rollback`/`deploy --existing-tag` first verify all four images exist at the tag; `terraform apply` always applies a saved plan (`-out`), never `-auto-approve` on an unseen plan; the plan file is deleted after use (it holds the session secret in plaintext) and is created under a private temp dir (`mktemp -d`, mode 700), never inside the repo.
- **No secrets in the repo or in `deploy.env`:** `deploy.env` holds project id, region, state bucket, registry repo name, optional budget/custom-domain values only. The session secret stays generated by Terraform (`random_password` → Secret Manager).
- **Auth model:** the operator's own identity (`gcloud auth login` + `gcloud auth application-default login`), needing at least Owner or the documented minimal roles on the project; the runbook lists the roles. No service-account keys, no WIF.
- **State:** GCS backend with a bucket created by `bootstrap` (versioning, uniform bucket-level access, public access prevention), not managed by Terraform; the script passes `-backend-config="bucket=…"`.
- **Terraform after simplification** keeps: APIs, Artifact Registry (+cleanup policy), VPC/subnet, the four runtime service accounts, Secret Manager secret + accessor for the gateway SA, the four Cloud Run services and their `allUsers` invokers (ruling from Plan 7 stays), optional budget. Removed: `deployer` SA, its project roles and `actAs` bindings, WIF pool/provider/bindings, `github_repository`, `github_deploy_branch`, the APIs only they needed (`iamcredentials`, `sts`) unless something else uses them, and the `deployer_service_account` / `wif_provider` outputs. `validate.sh` counts and README tables are updated accordingly.
- Runbook `docs/deploy.md` is rewritten (shorter): prerequisites, configuration, first deploy, regular deploy, rollback, smoke and TRUST_PROXY_HOPS verification, cost control, destroy, limits, pendências. Carry over every still-valid caveat from Plan 7 (two web URLs → use `web_url`; Direct VPC egress + internal ingress unverified until the first real deploy; WIF-free so no environment/branch settings; `allUsers` org-policy caveat; session loss on deploy; secret rotation via `-replace`).
- Bash scripts must run on macOS bash 3.2 (no empty-array expansion under `set -u`, no `mapfile`, no associative arrays, no `${var,,}`), `set -euo pipefail`, quote everything, no `eval`.
- Conventional commits; comments English, docs pt-BR; `CHECKLIST.md`/`WORKBOARD.md` honest (row `deploy` reopened for this plan).

## Review Focus

1. A mistyped or missing confirmation must never apply or destroy: any answer other than the exact expected string aborts with exit code ≠ 0 and no mutating command run (the fake-binary log proves it).
2. `destroy` must be impossible to run by accident: requires the project id typed, refuses when `project_id` in `deploy.env` is empty or `example`, and prints what survives destroy.
3. The saved Terraform plan (contains the session secret) never lands in the repo or in a world-readable path, and is removed on success, failure and Ctrl-C (trap).
4. `deploy` ordering: preflight → (build+push | verify existing tag) → terraform init/plan → confirmation → apply → read outputs → smoke; a failing smoke exits non-zero and tells which hop failed, without rolling anything back automatically.
5. Re-running `bootstrap` is idempotent (bucket exists, APIs already enabled, registry already applied) and never deletes anything.
6. Removing WIF/deployer must not leave dangling references in Terraform, validate.sh, README, runbook, the checker, `.gitignore`/`.dockerignore`, or CI lint scripts.

### Task 1: `infra/deploy.sh` with an offline test harness

**Files:**
- Create: `infra/deploy.sh`, `infra/deploy.env.example`, `infra/deploy.test.sh` (offline tests with fake binaries), `infra/lib/` only if needed (prefer a single file)
- Modify: `.gitignore` (ignore `infra/deploy.env`), `package.json` (scripts: `deploy` → `bash infra/deploy.sh`, `test:deploy` → `bash infra/deploy.test.sh`; also add `test:deploy` to the root `pnpm test` ONLY if it needs no Docker/cloud — it uses fake binaries, so it may be included), `infra/README.md`

**Interfaces:**
- `deploy.env` keys (all documented in the example): `PROJECT_ID`, `REGION` (default `southamerica-east1`), `TF_STATE_BUCKET`, `ARTIFACT_REGISTRY_REPO` (default `seguradora`), optional `TRUST_PROXY_HOPS`, `WEB_CUSTOM_DOMAIN_URL`, `BILLING_ACCOUNT_ID`, `BUDGET_AMOUNT_BRL`, `BUDGET_ALERT_EMAIL`, `DEPLOY_FAKE_SERVICES` (default true), `LOG_LEVEL`. The script maps them to `TF_VAR_*`/`-var` flags. `--env-file <path>` overrides the default `infra/deploy.env`.
- Subcommands: `help`; `check` (prerequisites: gcloud, docker + buildx, terraform ≥ 1.10, node ≥ 22, git; `gcloud auth list` has an active account; ADC file exists; `deploy.env` valid; prints missing items); `bootstrap` (enable `cloudresourcemanager` + `serviceusage`; set the ADC quota project; create the state bucket if missing with versioning/UBLA/PAP; `terraform init`; targeted apply of the Artifact Registry repo (and its APIs) with confirmation; `gcloud auth configure-docker` for the registry; idempotent); `build [--tag T]` (git-clean check, default tag `<short-sha>`; refuse existing tag; `docker buildx build --platform linux/amd64 --push` for web, gateway, chatbot, fake-services; print the tag); `deploy [--tag T | --existing-tag T] [--yes] [--allow-dirty]` (build or verify, terraform init + `plan -out`, show the plan summary, confirm, apply, print `web_url`, run smoke); `rollback --tag T [--yes]` (alias of `deploy --existing-tag T`); `smoke [--url U]` (default `web_url` from `terraform output -raw`); `status` (outputs + `gcloud run services list`); `destroy --confirm-project ID` (see Global Constraints).
- Exit codes: 0 ok, 2 usage/config error, 3 precondition failed, 4 user aborted, 5 smoke failed, 1 other.
- `deploy.test.sh`: creates a temp dir with fake `gcloud`, `docker`, `terraform`, `node` (for smoke), `git` scripts that append their argv to a log file and return scripted outputs/exit codes (via env vars), prepends it to `PATH`, runs `deploy.sh` for each scenario and asserts on log + exit code + stdout.
